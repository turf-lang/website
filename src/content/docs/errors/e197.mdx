title: "E197: An empty recover block"
description: "What compiler warning E197 means, and how to fix it."
order: 197
---

{/* Generated by scripts/convert-errors.mjs from the diagnostic registry of turfc 2.3.0. */}

A warning, on by default. Since TurfLang 2.3.

`recover ... run { }` handles a failure. An empty block handles nothing: the error is dropped without a trace, which is what `recover` exists to prevent.

<Code title="Example">
```turf
import fs;

fn main(): int {
    fs::mkdir("out") recover as err run {
    };                      // the error is dropped -- WARNING
    return 0;
}
```
</Code>

Handle the error in the block: report it, return it, or use a default:

<Code title="Example">
```turf
import fs;

fn main(): int {
    fs::mkdir("out") recover as err run {
        printline("could not create out/");
    };
    return 0;
}
```
</Code>

If ignoring the error is right, put a comment in the block saying why. A block holding a comment does not warn:

<Code title="Example">
```turf
    fs::mkdir("out") recover as err run {
        // the directory may exist already, which is fine
    };
```
</Code>

This is a warning, not an error -- compilation still succeeds. To silence it for a whole build, set its lint level to allow: `turf build --allow E197` (or `[lints] E197 = "allow"` in turf.toml).

Run `turf --explain E197` in a terminal to read this again.
