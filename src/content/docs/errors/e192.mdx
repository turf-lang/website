title: "E192: An integer converted to a pointer"
description: "What compiler warning E192 means, and how to fix it."
order: 192
---

{/* Generated by scripts/convert-errors.mjs from the diagnostic registry of turfc 2.2.0. */}

A warning, off unless its lint level is raised. Since TurfLang 2.3.

`x to T*` with an integer `x` makes a pointer to whatever happens to be at that address. The compiler cannot know what is there, or whether anything is:

<Code title="Example">
```turf
fn device(): int {
    unsafe {
        mut port: int* = 4096 to int*;   // WARNING (E192 at `warn`)
    }
    return 0;
}
```
</Code>

Get a pointer from what it points to -- `&x`, an allocation -- or write `null` for "no address":

<Code title="Example">
```turf
fn device(): int {
    mut value: int = 0;
    unsafe {
        mut port: int* = &value to int*;
        mut none: int* = null;
    }
    return value;
}
```
</Code>

This warning starts at `allow` in 2.3: turn it on with `turf build --warn E192` (or `[lints] E192 = "warn"` in turf.toml).

Run `turf --explain E192` in a terminal to read this again.
