---
title: "E082: You can't turn a maybe-null reference into a plain one without checking"
description: "What compiler error E082 means, and how to fix it."
order: 82
---

`&?Box` is "a Box or nothing"; `&Box` is "definitely a Box". Converting the first into the second with `to &Box` is a promise that it isn't `null`, and Turf only accepts that promise where it can see it kept. Copying the value out with `to Box` reads through the reference, so it needs the same check.

<Code title="Example">
```turf
struct Box { val: int }

fn bad(b: &?Box): int {
    mut safe: &Box = b to &Box;      // b might be null
    return safe.val;
}
```
</Code>

Check it first, and convert inside the check:

<Code title="Example">
```turf
fn good(b: &?Box): int {
    if b != null {
        mut safe: &Box = b to &Box;  // proven non-null here
        return safe.val;
    }
    return 0;
}
```
</Code>

Often you don't need the conversion at all: inside the `if b != null { ... }`, `b` can be used directly.

Only a variable can be checked, so only a variable can be converted. For a `&?Box` that is a field, a call result or a list element (`h.item to &Box`), store it in a variable first, check that, and convert inside the check:

<Code title="Example">
```turf
struct Holder { item: &?Box }

fn good(h: Holder): int {
    mut b: &?Box = h.item;
    if b != null {
        mut safe: &Box = b to &Box;
        return safe.val;
    }
    return 0;
}
```
</Code>

Run `turf --explain E082` in a terminal to read this again.
