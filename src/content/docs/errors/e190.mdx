title: "E190: A write through a pointer into an immut array"
description: "What compiler warning E190 means, and how to fix it."
order: 190
---

{/* Generated by scripts/convert-errors.mjs from the diagnostic registry of turfc 2.2.0. */}

A warning, off unless its lint level is raised. Since TurfLang 2.3.

A pointer made from an `immut` array (`&a to int*`) points at values declared never to change. Writing through it changes them anyway, behind the compiler's back, which may also have used the old values already:

<Code title="Example">
```turf
fn patch(): int {
    immut a: int[4] = [1, 2, 3, 4];
    unsafe {
        mut p: int* = &a to int*;
        p[0] = 9;                    // WARNING (E190 at `warn`)
    }
    return a[0];
}
```
</Code>

Declare the array `mut` if it is meant to change:

<Code title="Example">
```turf
fn patch(): int {
    mut a: int[4] = [1, 2, 3, 4];
    unsafe {
        mut p: int* = &a to int*;
        p[0] = 9;
    }
    return a[0];
}
```
</Code>

The compiler reports this only when every value the pointer could hold points into the same `immut` array. This warning starts at `allow` in 2.3: turn it on with `turf build --warn E190` (or `[lints] E190 = "warn"` in turf.toml).

Run `turf --explain E190` in a terminal to read this again.
